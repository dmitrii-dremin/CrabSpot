# Native assertion call-site check

This clarification applies to frozen equality contract B0859F44465883C6BEFCB461829C6F0128496E6DD6B0F527C2781964CFBDBD3A. The runtime method `check_class_assertion_site(&self, role:ClassAssertionNative, caller:MethodId, pc:u32) -> Result<MethodId,Box<StringBodyError>>` returns the canonical expected native MethodId on a successful site check. It charges zero additional Field work and grants no mutation capability. The engine compares this MethodId against the actual selected target before publishing a pending call, and again before resuming it. An inconsistent pending target fails before registration, query count, result or caller-PC publication.

For a newly selected supported native, perform ordinary static member resolution, classification, fixed-shape checking, typed argument extraction, generic reference profile and argument validation, caller result-space preflight, then readonly site/target authorization. Publish the fixed pending record only after these checks, then request initialization. Thus an operand failure takes precedence over an unauthorized caller site. An ordinary Java target continues through its existing path.
