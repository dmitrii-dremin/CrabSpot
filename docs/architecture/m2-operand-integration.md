# Operand-time VM exceptions: integration evidence

The [frozen contract](m2-operand-vm-exceptions.md) extends the accepted Throwable
construction continuation to ArrayIndexOutOfBoundsException,
NegativeArraySizeException, ArrayStoreException and ClassCastException. Runtime
and execution component reviews have cleared the integrated sources. Combined
local verification has passed, including both public product matrices. The
technical director accepted the bounded increment and authorized publication.
This is not M2 completion or general Java compatibility.

## Behavior and boundaries

The existing instruction services retain the original index, length, requested
dimension and actual type facts at the failing operation. Detailed additive
results share one implementation with the earlier symbolic APIs. Success does
not repeat name lookup, assignment checks, stack pops or fuel charging.

A sealed five-class discovery plan supplies four additional constructor targets
and their genuine IndexOutOfBoundsException parent. The common pending engine
constructs real Java exceptions, consumes the original fault snapshot and
dispatches at the actual instruction. Existing Arithmetic behavior and explicit
Arithmetic-only wrappers remain supported. The ordinary convenience launcher
uses the new Auto profile; missing or invalid roles after a valid Throwable
profile are explicit errors.

Messages use bounded UTF-16 buffers with separate work, per-message, cumulative
message and temporary-storage limits. Bounds and negative-size diagnostics follow
the primary observed policy. Cast diagnostics name the actual types without
inventing unsupported module or Java ClassLoader identities. The underlying
specification does not require identical vendor-specific message decoration.

General NPE production and extended messages, monitor/catch-resolution producers,
non-Error initialization wrapping, Java stack-element population, arbitrary
class loaders/modules, threads/JMM, GC and broad native/library integration remain
open. No resource or unsupported host failure is silently converted into a Java
exception.
