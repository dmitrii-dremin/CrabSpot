## Observable target

An ordinary directory launch on a supported compact Java 21 image executes the supplied `String.length()I`, `String.isEmpty()Z`, package-private `String.coder()B`, `String.<clinit>()V` and the selected comparator constructor. The interpreter uses the ordinary verified Code, method selection, field resolution, initialization, frame, operand, handler, monitor and instruction budgets. Each entered Java body has its own actual MethodId, Code, PCs and frame. A cached or direct call obeys the same body authority as a cold virtual call. No new native computes length, emptiness, coder, initialization or comparator construction. The existing native intern and getClass services retain their own authority.

The required first implementation is compact byte-array storage with low UTF-16 byte first, on a matched bootstrap image. This private layout policy covers the measured Zulu 21.0.7 `java.base` String (49,134 bytes, SHA-256 D4F87FCDE6A7A0F4FEA37F7C56E29279E94A9DA55CCB41A6155D68CB44FE25D0). Its actual five-class reference observation and exact instructions determine the acceptance tests. The 42,766-byte OpenJ9 String (25BC3E38A28F35A537715C22EA57ABE9C78DB5C630535CC603345B92F39278CE) has the same observed length and default compact layout, but its initializer reads a VM flag, enters JITHelpers and builds a table. It is a required unsupported-shape control for this binding. Record the specific Temurin image and actual body-path result per hosted job. Noncompact mode is a separate reference observation.
