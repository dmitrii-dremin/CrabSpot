# Next: reference arguments and results

Status: proposed direction on 2026-11-04 after the bounded approval in `m2-multidimensional-arrays-review.md`. This note does not authorize implementation. An exact invocation/type/budget contract must precede dispatch. Full M2 remains open.

Extend the runtime-aware body graph to reference parameters and results, including areturn, after the array gate. This allows ordinary object and array values to cross existing static-helper, virtual, interface and ordinary-special calls without using fields as an indirect exchange mechanism. Reuse MethodId-keyed prepared bodies, actual reference identities, shared frames and assignment services. Earlier metadata-only numeric and primitive-heap entry points should retain their existing signature boundaries.

The exact design must distinguish the call-site descriptor, resolved declaration and selected implementation. Resolve nominal parameter/result identities using the appropriate defining loaders, without importing cast caller-access checks into descriptor identity. Preserve all method selection/access/null/finality rules and explicitly define when argument checks occur relative to selection and callee preparation. Receiver compatibility remains separate from parameter compatibility. JVM method loading constraints concern descriptor identities across loaders; checking a value against one selected descriptor is not a substitute for those obligations. See [JVMS loading constraints](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.3.4) and [method resolution](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.3).

A feasible first boundary is to reject nominal-reference signatures when the relevant caller, resolved declarer and selected declarer loaders differ, even when the supplied reference is null or current resolver answers coincide. Primitive-leaf array signatures can use the explicit bootstrap identity. This is a proposed temporary unsupported boundary, not full constraint enforcement; the exact contract must audit overriding and host-root cases before adopting it. The actual argument object's defining loader need not match the descriptor's loader if its identity is assignable through the admitted graph.

Use typed Reference values in existing local/operand slots and preserve opaque handles across calls and returns. Pin null behavior, foreign/stale handles, array covariance and incompatible host values as structured validation failures, without inventing ClassCastException or ArrayStoreException for malformed invocation/return values. areturn must validate against the declared result and transfer exactly the returned identity to the caller; host-visible reference results remain owned by the supplied heap. Constructor/uninitialized values remain unsupported and cannot be inferred from ordinary admitted handles.

Prepared signature metadata and resolution work need explicit bounds. Keep descriptor parsing, complete UTF-16 work charges, shared name bindings and any retained resolved types bounded by existing class/code policies or a justified new limit. Avoid a second resolver, repeated graph copies, signature strings as unchecked loader identities or an unbounded per-call cache. Preserve exact fuel/frame/slot/code behavior, receiver category-one layout, mixed Long/Double argument ordering and return-transfer provenance.

Evidence should include null/self/distinct-object/array parameters and returns; mixed primitive/reference signatures; all call forms and current declaring origins; inherited/default/private/special selection; actual covariance; aliases/cycles; recursion; inaccessible descriptor types; malformed values/returns; loader boundaries and failure order; exact budgets and persistent earlier effects. Genuine JDK wrappers can compare numeric observations of identity and mutations, while synthetic tests inspect returned heap identities directly. Reference signatures do not add constructors, initialization, generalized cross-class static lifecycle, handlers, mirrors or Java startup.
