# Session object allocation and constructor execution

Status: bounded implementation approved by the technical director on 2026-11-04 after frozen source review and the fresh-build independent gate. See `m2-construction-review.md` for corrections, exact source identities and 947 debug / 860 optimized passing tests. The implementation contract was frozen before dispatch from d3ad54f; its original dispatch hash is retained in the review and worker manifests. Fresh hosted CI remains pending publication. Full M2 remains open. No NanoSpec.

## Scope and specification boundary

Implement new (0xbb) and constructor invokespecial in the existing InitializationSession engine. The same engine must execute real constructor Code, including the explicitly supplied bootstrap Object constructor. Ordinary body entry points continue to reject new and constructor calls; host-supplied instance storage remains an explicit service, not proof that a constructor ran. Session initialize and run_static gain construction with default limits; their existing arguments and results remain compatible.

The normative references are [JVMS 2.9.1](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.9.1), [initial constructor frames, 4.10.1.6](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-4.html#jvms-4.10.1.6), [instruction type rules, 4.10.1.9](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-4.html#jvms-4.10.1.9), [method resolution/access](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.3), [new](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-6.html#jvms-6.5.new), [invokespecial](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-6.html#jvms-6.5.invokespecial), and [putfield](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-6.html#jvms-6.5.putfield).

This increment dynamically enforces the construction protocol on executed paths. It does not implement the full verifier: stack-map merges, all control-flow proofs, verification-time exception edges and rejection timing remain open. Errors for malformed runtime protocol are structured host errors, not fabricated VerifyError objects. Successful execution is not a verification certificate. Preserve all existing unsupported linking, loading-constraint, nest, native, monitor, String, VM-exception materialization, wrapping and startup boundaries. No global heap initialized/poisoned bit may substitute for the frame protocol.

## Public interfaces and ownership

Public runtime Value, ValueKind, Reference and HeapRef remain unchanged. Uninitialized values are private to the interpreter. Add the following runtime service surface (opaque types have private fields and no Clone/Copy):

```rust
pub struct ResolvedNew; // claim/snapshot, origin, CP index, actual class
impl ResolvedNew { pub fn class(&self) -> ClassId; }

pub enum ConstructorReceiverKind { Allocation, This }
pub enum ConstructorFieldReceiverKind { Ordinary, UninitializedThis }
pub struct ResolvedConstructor; // claim/snapshot, selected MethodId, receiver
impl ResolvedConstructor { pub fn method(&self) -> MethodId; }

impl FieldResolutionContext<'_> {
    pub fn resolve_new(
        &mut self, claim: &InitializationClaim, origin: ClassId, index: u16,
    ) -> Result<ResolvedNew, ConstructionAccessError>;
    pub fn allocate_new(
        &mut self, claim: &InitializationClaim, access: &ResolvedNew,
    ) -> Result<Reference, ConstructionAccessError>;
    pub fn constructor_invocation_shape(
        &mut self, origin: ClassId, index: u16,
    ) -> Result<MethodValueShape, ConstructionAccessError>;
    pub fn resolve_constructor(
        &mut self, claim: &InitializationClaim, origin: MethodId, index: u16,
        receiver: Reference, kind: ConstructorReceiverKind,
    ) -> Result<ResolvedConstructor, ConstructionAccessError>;
    pub fn write_constructor_field(
        &mut self, claim: &InitializationClaim, constructor: &ResolvedConstructor,
        index: u16, receiver: Reference, value: Value,
        kind: ConstructorFieldReceiverKind,
    ) -> Result<(), ConstructionAccessError>;
}
```

These are checked metadata/memory services. They neither certify successful construction nor expose a completion setter. The trusted interpreter is responsible for the current frame role, uninitialized provenance, initialization completion and continuation ownership. In particular, allocate_new returns a storage identity to the interpreter; the engine must tag it before any bytecode or host result can observe it. The host already has explicit low-level default-storage allocation; this API must not relabel it as constructed.

Claim checking reuses the existing permanent initialization claim and fixed graph/static/exception/type snapshot. Tokens are scalar metadata fingerprints, not copied UTF-16 names, descriptors, Code, graphs or live alias collections. Revalidation checks immutable handles/indices/flags and heap identity before use; it must not recompare long strings without charging their inspection. No public token issuer accepting arbitrary fields or boolean allow_final is added. Constructor authority is tied to the resolved constructor declaration and original constructor receiver; it is moved into that constructor's frame and is never inherited by helper frames.

Add interpreter ConstructionLimits { max_alias_steps: u64 }, default 1_048_576. Add initialize_with_construction_limits and run_static_with_construction_limits with the existing respective argument list followed by ConstructionLimits. Existing initialize/run_static delegate with default limits. Add last_construction_steps(&self) -> u64. This limit controls frame scans, not Java allocation quotas; each evaluation resets it at the existing evaluation boundary, including explicit initialize roots and later preflight failures. Reserved scan work remains consumed if a later operation fails. No constructor can be selected as a host root. Keep one engine, one initialization scheduler, one MethodId cache and the existing exception dispatcher.

ConstructionAccessError contains direct Java(ConstructionJavaError), Method(Box<MethodAccessError>), Field(Box<FieldAccessError>), Type(Box<TypeAccessError>), Initialization(Box<InitializationAccessError>), Instance(Box<InstanceError>), plus InvalidMetadata(&'static str), InvalidReceiverKind, InvalidConstructorOwner { origin: MethodId, owner: ClassId }, InvalidConstructorReceiver { expected: ClassId, actual: ClassId }, and TokenMismatch. ConstructionJavaError is NoSuchMethod, NoSuchField, IllegalAccess, IncompatibleClassChange, NullPointer, or Instantiation. Preserve Error::source for wrappers. At the new service's intentional method/field/type access boundary, translate only direct expected Java variants to direct ConstructionJavaError; never recursively unwrap nested Java-shaped errors.

Add ExecutionErrorKind::ConstructionAccess(Box<ConstructionAccessError>), ConstructionProtocol { reason: &'static str }, ConstructionStepLimit { limit: u64, required: u64 }, and ConstructionAccountingOverflow { resource: &'static str }. Keep method, PC, call-site and initialization_class provenance. Do not return an unfinished receiver as a public diagnostic value. Add VmExceptionKind::InstantiationError and route it through the session's existing UnsupportedVmException policy. All new VM-produced outcomes remain unmaterialized host policy errors before handler matching; supplied Throwable references retain ordinary checked dispatch.

## Private frame values and alias identity

Use a private operand/local representation with ordinary Value and an uninitialized construction token. A token is one computational slot. It retains the actual heap identity, allocation class as needed, and either an allocation identity/site or a constructor-activation identity. An allocation key includes the actual allocated handle, never just class or bytecode PC. A This key distinguishes constructor activations, including recursive this(...) invocations on the same object. Activation numbers are checked, nonwrapping, evaluation-local integers. No global live-token registry is necessary.

Loads/stores of reference locals, including fixed and wide forms, and legal category-one stack manipulation may transfer these private values without converting them. This includes legal pop/pop2 discard; "ordinary extraction" below does not prohibit those stack instructions. Existing long/double local overlap and stack-category rules remain intact. Extraction into an ordinary Value or ordinary reference service rejects a token with ConstructionProtocol. This covers reference arguments, returns, casts/instanceof, arrays, field values, static values, athrow and ordinary instance-call receivers. Numeric misuse retains the established computational kind error where applicable. No generic pop_any may accidentally turn a token into Value::Reference.

The generic-reference branch instructions ifnull/ifnonnull and if_acmpeq/if_acmpne also accept private tokens. Test their nullness/actual heap identity without promotion; compare the underlying object identity, not the frame alias key. Keep existing handle validation for ordinary references and validate private token handles without exposing an ordinary Value. A token is never null; an unusable invalidated slot is not a reference operand. These branches do not perform assignment checks or alias scans. This distinction follows their generic-reference type rules; checkcast/instanceof still require an initialized reference.

Original Java 65 stack-map probes passed all four unfinished-reference branch forms on Zulu 21.0.7 with -Xverify:all. This corrected an overrestrictive draft rule before dispatch; preserve the positive cases in permanent coverage.

Only constructor invocation, the narrowly checked pre-chain own-field receiver, private identity/null branches and engine bookkeeping may inspect its raw storage reference. A helper receives only ordinary argument Values. A constructor token may be discarded; unused storage remains allocated under existing heap accounting.

An ordinary method may return an unrelated ordinary result while unused unfinished values remain in its locals or discarded operand stack; frame disposal does not certify their construction. The constructor chain obligation, rather than the mere presence of any unfinished allocation, is what prohibits a constructor from returning prematurely.

Track the constructor chain obligation independently of local0, so overwriting local0, losing every alias or constructing another object cannot permit premature return. Its state is Pending, Complete or Failed. A non-Object constructor begins Pending with an uninitialized This in local0. Parameters are ordinary checked Values. The designated bootstrap Object constructor begins Complete with ordinary local0, but its actual Code still executes. An unrelated same-name/root identity never obtains this base rule. At this base-case boundary validate the bound Object identity as a public, concrete, non-interface class with no superclass; unsupported/corrupt core metadata is a host InvalidMetadata failure. Do not add a new eager requirement to old sessions that never execute construction.

The lazy base validation belongs to resolve_constructor when the selected owner equals the bound universe Object. It follows the resolved-owner and receiver/null/relation checks and precedes returning the token, hence precedes body preparation and semantic argument assignment. These constant-size checks add no name traversal or separate work charge beyond the already charged lookup and relations.

new also observes the allocation-site rule within its current frame. Before suspension, check that no uninitialized Allocation token from this same method/PC is on its operand stack; reject a repeated live stack-site token. On successful publication of the new allocation only, invalidate local tokens from the same allocation site before pushing the new token. A failed resolution, initialization or allocation does not publish a new token or invalidate these old locals. Tokens at other sites and ordinary references are unaffected. Actual handles still distinguish separate allocations and activations. This runtime rule does not replace control-flow verification.

## new: resolution, suspension and publication

At a reached 0xbb, non-session profiles return their existing UnsupportedInstruction gate before attempting the new service. In a session:

1. Debit the bytecode's fuel once. resolve_new checks claim/context/origin admission, Class/Utf8 structure, and rejects an array spelling as invalid metadata before resolving a target. Resolve using the current declaration's loader, complete class-name work and existing symbol/unit/callback limits, and caller access. Target/interface access failure precedes the instantiability decision.
2. An accessible interface or abstract class gives direct Instantiation. A concrete target must be in the fixed admitted graph and in the explicitly bound Object universe. Retain its actual ClassId in ResolvedNew; do not resolve a constructor here.
3. Check room for one operand slot and fallibly reserve any needed stack/continuation capacity before suspension. Precharge the single allocation-site scan, then inspect the stack for an old same-site token. These are dynamic/profile preflights, not claims about verifier error timing.
4. Request initialization of the actual resolved class through the existing scheduler. Preserve original PC, next PC, access token and the already consumed fuel. Caller locals/stack, including other uninitialized values, remain intact while initializers run. No allocation occurs yet. Initialization failure dispatches at the original new PC under the established Error/host policy.
5. After successful initialization (including the established same-evaluation recursive case), revalidate the retained token without re-resolving/recharging its name. allocate_new uses existing atomic instance allocation and shared quotas. Allocation failure is a host resource error; completed initialization/effects remain. There is no synthesized OutOfMemoryError.
6. Infallibly finish the previously funded local invalidation, wrap the freshly allocated identity as an Allocation token, push it and advance to next PC. There is no callback or fallible step between heap publication and private token publication. Resume cannot allocate twice or debit fuel twice.

For public low-level allocate_new, the runtime validates claim/token/class and instantiability but does not know the session's lifecycle record. Its documentation must say that the engine performs step 4. This is the same separation as the existing initialization installer; no runtime success setter is introduced.

## Constructor symbolic resolution and call preparation

Only a session b7 whose structurally valid Methodref NameAndType names <init> enters this path. Ordinary b7 continues its existing path without additional charged shape inspection. The fixed discriminator checks Methodref, NameAndType and name Utf8 only; a wrong tag, malformed structure, InterfaceMethodref or <clinit> follows the existing ordinary b7 structural/special-name error path. Thus parser-invalid InterfaceMethodref<init> in a private corruption test may retain MethodAccess::UnsupportedSpecialMethod instead of a new wrapper. Non-void constructor descriptors fail the constructor shape check. Old body profiles continue their previous special-name failure. Do not copy/parse a long descriptor in the discriminator outside the charged shape service.

constructor_invocation_shape checks admitted origin, Methodref/Class/NameAndType/Utf8 structure, exact name and void result, then returns compact computational parameter kinds and slots. Its descriptor charging is the existing reference-signature rule; all-reference-null cases are not exempt. It defers unsupported array-owner spelling to selection after typed operand extraction, preserving existing instance-call ordering.

The interpreter extracts ordinary typed arguments in reverse order and then a private constructor receiver token. Ordinary Reference (including null), an unusable value or a numeric value is not an unfinished construction receiver. Reject it as a host protocol/kind error; never re-run a constructor on an ordinary object. Validate This against the current actual constructor activation and its Pending obligation before passing the raw receiver to the resolver. An Allocation token is allowed in any session body, including another constructor before chaining.

resolve_constructor performs claim/origin validation, re-inspects the symbolic signature with its usual charge, resolves the owner and applies class accessibility/kind, method lookup, member accessibility and the conservative nominal loading constraint. Public/private/package/protected rules retain loader-qualified packages. Private access from another class remains UnsupportedNestAccess. A nominal parameter leaf requires origin and resolved declaring loaders to agree, even for null arguments. Primitive-leaf arrays do not introduce that restriction.

Important ordering: method resolution is the JVMS 5.4.3.3 phase, followed by the invokespecial constructor-owner check. Do not execute an inherited constructor, but also do not suppress an earlier ancestor method-resolution/access/loading failure by immediately returning NoSuchMethod solely because the symbolic owner lacks its own declaration. Once resolution succeeds, a constructor declared outside the symbolic owner gives NoSuchMethod. No ACC_SUPER redirection, interface default selection as an executable constructor, overriding/final-chain audit or receiver-directed virtual selection applies. Parsed valid interfaces cannot declare constructors. Preserve the existing method-lookup work accounting for every examined class/declaration; any necessary fallback must not bypass its existing budgets.

Coordinator development probes on Zulu 21.0.7 corroborate this order: absent Child.<init>(I)V resolves a public ancestor declaration before NoSuchMethodError, but inaccessible package/protected/private ancestor declarations fail access first. The current private-nest boundary remains an explicit host UnsupportedNestAccess instead of claiming complete private-access resolution. Separate original-bytecode probes accept own final primitive/reference writes before Object.<init>, reject inherited or symbolic-subclass-alias pre-chain writes, and produce IllegalAccessError for a parent-final write after the super call. These scratch probes guide permanent synthetic tests; they are not substitutes for the frozen acceptance evidence.

Then check receiver relations. The public runtime service reports a null receiver as direct NullPointer after successful resolution/constructor-owner/category checks; bytecode's earlier private-token requirement makes that service boundary unreachable from a well-formed constructor call. Foreign/stale/non-instance receivers remain host errors. Allocation requires actual allocated class == symbolic owner. This requires that origin is a real instance constructor and symbolic owner is exactly its declaring class or its admitted direct superclass; actual receiver must be a class instance at or below the origin class. Protected constructors outside the runtime package retain the additional receiver restriction for an Allocation invocation: the allocated class must be at or below the accessing class. Do not broaden protected subclass into general assignment. This/super chaining uses its precise owner relation rather than ordinary invokespecial's ACC_SUPER machinery. Invalid structural relations are host diagnostics, not invented Java exceptions.

The result is a receiver-bound ResolvedConstructor selecting the actual MethodId. Prepare it under a distinct Constructor role, check Code/handler/cache limits and actual frame/slot reservation, validate ordinary arguments against the selected declaration's descriptor, and only then enter the frame. Constructor profile validation must not invoke the ordinary receiver-wide nominal override audit: constructors do not override. Preserve selected-declarer identity-only argument resolution and null value shortcuts after the symbolic loading guard. Descriptor shapes contain no owned nominal-name tree. Every call resolves/access-checks again, even when Code is cached.

Constructor invocation itself is not a second class-initialization trigger. The enclosing allocation already requested initialization; this/super delegation runs within that allocation's protocol. Constructor entry remains distinct from Ordinary and Initializer on every cache hit. A callable constructor is nonstatic, void, nonnative, nonabstract, nonsynchronized Code under the supported parser/version rules. Its declaring class may be abstract: a lawful superclass constructor must still execute for a concrete descendant. Native/synchronization and malformed Code remain explicit preparation failures. No role can invoke <clinit> explicitly; b6/b8/b9 remain forbidden for <init>.

## Normal and abrupt constructor completion

A constructor return must be void and its chain obligation Complete. This check is independent of locals and precedes selected-method return validation, alias-work charging and frame removal. Reuse check_method_return(method, None), including its existing reference-bearing descriptor charge, without an ordinary override audit. A successfully returned constructor converts all matching unfinished receiver aliases in its immediate caller frame to ordinary references. If that receiver was the caller's This token, also change its obligation to Complete. If it was a separate Allocation token, do not change the caller's own chain obligation. A constructor's internal This token is distinct from the key held by its caller; retain the caller key in call-boundary metadata.

Precharge alias work and verify caller identity/origin/frame invariants before removing the callee or changing aliases. The conversion is allocation-free and cannot partially fail. Return does not create another object or push a result; the usual dup/local aliases provide access to the constructed object.

On a supplied exception escaping a constructor frame, invalidate the matching caller aliases before searching/installing a caller handler at the saved b7 PC. Matching local slots become unusable; the discarded operand-stack aliases cannot survive handler installation. If the failed call was on the caller's This, mark its obligation Failed. A handler may perform unrelated work or rethrow, but cannot revive those aliases, retry that chain or return successfully. A throw caught inside the constructor before it escapes does not trigger caller invalidation. Existing exception-table ordering, catch resolution, frame/unwind/row limits and provenance remain in force.

Distinguish an ordinary helper throwing before the constructor's chain call: if that exception is caught in the constructor, its This aliases and Pending obligation remain intact, so a subsequent lawful this/super call may complete it. The constructor-boundary rule is not a blanket invalidation on every exception while a constructor is Pending. An original Java 65 handler probe with full-frame uninitializedThis corroborates this case on Zulu 21.0.7.

Ordinary references published after an inner constructor's chain completed are not revoked when an outer constructor fails. Fields, arrays, static roots and other frames holding those ordinary references remain usable. Do not clear the object, undo writes, reduce heap counts, poison the heap entry or globally convert aliases. Every constructor boundary invalidates only the unfinished key held by its immediate caller. An Error escaping into a class initializer still follows the existing erroneous-class procedure; a constructor failure after class initialization does not make that class erroneous.

Host failures/panics terminate the evaluation and drop all transient frames/tokens without requiring more policy budget or allocating cleanup metadata. Existing initialization RAII marks only still-active class initializations Aborted. Completed/Erroneous records, prior side effects and legitimately escaped references remain. No uninitialized value may become a public return, uncaught exception or persistent session retained-root value during cleanup.

## Constructor putfield and final authority

The engine uses write_constructor_field only in an actual Constructor frame, with that frame's receiver-bound token. Helpers use the ordinary write_field service. All raw heap setters and ordinary context writes keep their final-field prohibition and checked non-null assignment boundary.

For an ordinary receiver in a constructor frame, field selection/access/loading and static-category checks precede finality and receiver/value validation as before. A final field is writable only if its actual declaring class is the current constructor's declaring class. Do not add an unsupported requirement that the ordinary receiver must equal local0: JVMS final authority is declaration/method based. The receiver must still satisfy normal symbolic/protected receiver checks, and reference values use the existing source-first, identity-only selected-field assignment service.

For a private UninitializedThis receiver, the engine first requires its current Pending This key. The runtime additionally requires receiver == the constructor's bound receiver, the symbolic Fieldref owner == current constructor class and the selected field declared by that class. This is the only pre-chain receiver exception; an Allocation token, inherited field or alternate symbolic superclass/child owner does not qualify. The value must already be an ordinary Value, including ordinary/null references; unfinished this cannot be stored as a value. Apply the same final-own-declaration, primitive narrowing/raw bits and non-null assignment checks before mutation.

Exact runtime order is claim/token validation, field selection/access/loading, static category, final authority, then the early-receiver structural restrictions, normal receiver checks and value assignment. For UninitializedThis, a wrong symbolic owner produces InvalidConstructorOwner { origin: constructor.method(), owner: symbolic_owner }; otherwise a wrong declaring owner uses the actual field owner in that variant. A receiver different from the token's invocation receiver produces InvalidReceiverKind. A final field owned by another class still fails direct IllegalAccess at the earlier final-authority stage. Token corruption remains TokenMismatch/InvalidMetadata, not a Java outcome.

Use a narrow private commit proof/token for the authorized write. It rechecks receiver/storage ownership, exact owner-qualified field/slot, descriptor kind, final authorization, source handle and metadata fingerprint before mutation. There must be no public general-purpose final bypass, no unchecked final reference commit and no external callback between proof and publication. Late failure leaves all fields/roots unchanged. Final writes inside a same-class helper, a different constructor class, an ordinary body or <clinit> remain forbidden. The constructor's own role can perform repeated lawful writes; do not invent a write-once bit.

## Work, memory and roots

Existing frame count, aggregate reserved slots, prepared Code bytes, handler count, bytecode fuel, exception dispatch work, initialization steps/plans, class/instance/field-slot quotas and context symbol/name/work limits all remain shared. Constructor frames count exactly like other frames. Each new instruction consumes one fuel unit; each executed constructor bytecode, including return, consumes normal fuel. No replay cost is introduced on initializer suspension.

Construction alias work is separately checked u64 accounting. For a frame-wide allocation-site check/invalidation, successful alias promotion or exceptional alias invalidation, charge atomically 1 + local-slot capacity + actual operand-value count before the first scan. Local-slot capacity means logical max_locals/Locals.slots.len, never allocator spare capacity; operand-value count means values.len, so a Long or Double counts as one inspected value. This pays for examining every local slot (including Empty/Continuation) and every currently stored stack value once; local and stack phases may occur at different points around a suspended new, but the caller is unchanged between them. No partially charged scan or partial rewrite. Ordinary frame returns, identity/null branches and reference moves without construction work add no alias steps. Overflow is ConstructionAccountingOverflow, and zero/exact/usizeMAX/u64MAX-style small-actual policies must work without policy-sized allocation.

For allocation, the new runtime service must additionally precharge its actual heap-layout traversal: one context step before each class shape inspected plus one per declared instance-field entry used to create defaults. Use existing incremental step semantics, not atomic bulk funding: exhausted work retains its accepted prefix and allocates nothing. The actual per-class entry count may be read from checked retained shape metadata, without a redundant descriptor scan. Fully funded work remains consumed when a later heap quota/allocation check fails. Shared instance quotas/normalization/publication stay as in allocate_instance. The public low-level allocate_instance API retains its existing behavior and charges. Constructor metadata lookup/signature/type/field work reuses existing counters and repeats on cache hits; no hidden unbounded name scan or alias registry is introduced.

Retained construction tokens/continuations are constant-size or sized by actual argument count, never by configured maxima. Use fallible reservation for new metadata and avoid placing a large token payload in every legacy frame. An opaque token must have a single owner across suspension/entry/unwind. All per-frame scans and constructor chains are iterative. Dropping a long constructor chain or cyclic object graph does not recursively walk Java references.

Heap children and static-root iteration automatically expose ordinary references stored by lawful constructor writes, preserving aliases and existing deterministic location order. Session retained_roots continues to mean retained initialization-failure causes, not a history of every allocation. Frame tokens, constructor receivers, pending values and locals/stacks are transient execution roots conceptually; there is still no complete active-frame GC root API and no collector. Orphaned failed/unused allocations persist in the arena and retain quota. Do not invent reclamation or claim tracing coverage.
