The fixed five-source/nine-class guest inventory, separately compiled observer, exact three-operation historical projection, historical source/class pins, immutable reference rows, canonical tool hashing and read-only check mode preserve the intended scope. One blocking v1 provenance defect was found: the first staged-file hash snapshot occurs after both compilation subprocesses. A subprocess can alter an archived class or staged source/control before that snapshot, and later checks compare against the already-modified staging tree rather than captured input buffers. The independent reproducer changed only the archived ThrowableMain SourceFile spelling during compiler setup. The pinned compiler still reproduced its own outputs exactly, and all 20 application observations passed despite execution of a differently hashed archived class. This is a provenance defect, not a change in guest observable behavior.

Independent validation ran all 15 supplied regression groups with zero skips, including the real Java check, in a director-owned copied standard-layout workspace. The added real-JDK reproducer is `review_throwable_portable_v1.py`; its result is `throwable-portable-v1-staging-reproducer.json`, and regression output is `throwable-portable-v1-tests.log`, all in this directory.

Requested correction: compare every staged source/control/archived-class input to its captured authenticated buffer after writing and around compilation, before any VM execution, then retain the final comparison. Add an injected subprocess mutation regression proving refusal before VM launch. The coordinator reports these changes implemented with 16 passing groups, but a corrected immutable v2 snapshot has not yet been reviewed. V1 is not cleared for publication; no other source blocker was found in this bounded readback. CI integration and frozen-source recheck remain separate publication conditions.
