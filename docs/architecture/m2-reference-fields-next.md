# Next: non-null ordinary instance fields

Status: historical direction, superseded by the exact contract in `m2-reference-fields.md` and bounded approval in `m2-reference-fields-review.md` on 2026-11-04. The rationale below is retained; the next proposed increment is `m2-reference-arrays-next.md`. Full M2 remains open.

The next coherent increment should permit checked non-null instance-reference field stores through the existing runtime-aware field service and b5 instruction. This uses the new assignment relation to create useful object graphs without adding another heap payload kind or widening method signatures. Existing getfield, reference locals, casts and invocation receivers can then consume those graphs. Primitive arrays can also be stored in compatible reference fields.

Keep direct public heap writes conservative: an untyped low-level store must not become a bypass around descriptor identity and assignment checks. The context should perform all checks, then use a narrow crate-private commit operation. All failed checks must leave the field value and child-handle enumeration unchanged. Final fields remain prohibited; default-only static storage stays unchanged.

Resolve the declared field type using the selected field's declaring loader and immutable descriptor. Reuse borrowed name bindings and the shared relation. Do not apply a cast target's caller-access check to the field descriptor type: an accessible public field may have a type that the caller cannot name. Field/member access and value assignment are separate obligations. Preserve the existing explicit cross-loader nominal loading-constraint restriction for this first storage increment; removing it later requires a concrete constraint-enforcement contract, not an assumption that equal descriptor text means equal type.

The exact contract must preserve existing field resolution, access, static/final and receiver failure order. It must pin source-handle validation, universe requirements and descriptor-resolution work for a non-null value, while keeping old numeric and null stores usable without a universe. An incompatible reference in an unverified body is a structured host type failure, not an invented ArrayStoreException. No mutation may occur before every applicable check succeeds.

Acceptance should include self-references, aliases, overwrites, null clearing and cycles; inherited and hidden owner-qualified fields; ordinary/interface/Object targets; all primitive-array identities and incompatible nominal/array types; final/access/null/static order; foreign/stale handles; exact work limits and binding failure atomicity. Enumerating child handles should expose each non-null reference location, including aliases and cycles, without recursively tracing it. That is an edge-enumeration service, not garbage collection.

Genuine numeric wrappers can store this, manipulate links retrieved through fields, store locally allocated primitive arrays, cast retrieved values and invoke numeric instance methods. JDK outputs and independently checked state should cover successful writes and failures after earlier effects. Public runtime tests can additionally supply separately allocated receiver/value objects without adding Java reference arguments to the execution API.

After this increment, reference-array storage and anewarray/aaload/aastore can reuse the same type identities, checked assignment and child-edge conventions. Reference call signatures, constructor uninitialized-reference rules, static initialization, exception identities/dispatch and collection remain separate gates. No ordinary stored handle constitutes a completed constructor or lifecycle proof.
