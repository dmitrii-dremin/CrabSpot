# Next runtime-identity-aware call increment

Status: superseded by the authorized concrete contract `m2-virtual-calls.md` on 2026-11-03. This note is retained as design rationale.

The next coherent executable step should let instance bodies call ordinary instance methods using managed receivers and registered method identities. Start with numeric/void explicit parameters and results, preserving the current host-supplied storage/body-kernel boundary. Constructor invocation remains separate: a default-storage handle is not proof of completed construction, and invoking `<init>` requires uninitialized-reference and constructor rules.

Specify a reusable method-resolution and receiver-dispatch service before adding invokevirtual. Preserve exact loader/class identity, runtime-package access, protected receiver rules and explicit nest/loading-constraint limitations. Method resolution and runtime selection are different operations: inherited declarations, overrides, private/static/final methods and interface/default-method candidates cannot be collapsed into a same-name superclass search. If the first lawful subset excludes an interface/default case, detect it and return explicit unsupported behavior rather than silently choosing another method. Define missing-method, access, staticness, abstract-target and null ordering against the selected JVMS release.

Generalize the existing shared engine to key prepared code and frames by MethodId when calls cross declaring classes. Each frame needs its own declaring constant pool and runtime origin; field accesses must follow that frame, not the original entry class. Carry call-site provenance across class boundaries. Share instruction fuel, active-frame/slot reservations and prepared-code limits across the entire call graph, with bounded method-resolution caching and no Rust recursion. Existing static and array/field entry points must retain their guarantees.

The concrete contract must decide how the runtime context exposes method services without duplicating the admitted graph or coupling runtime to the interpreter. It must distinguish callable body selection from class lifecycle and verification proofs. Ordinary receiver values may move between frames as the implicit receiver while explicit reference parameters/results and non-null field stores remain outside the initial subset.

Acceptance should use genuine Java hierarchies with overrides, inherited bodies, hidden fields, mixed-width arguments, recursive and mutually recursive calls, null receivers and persistent effects before failure. Add synthetic resolution/access/selection edge cases, cross-loader same-name identities, exact resource boundaries and cache-mode regressions. Preserve all 8,838 execution comparisons and both 151-case memory-service oracles. Constructor protocols, invokespecial/interface semantics, exception dispatch, initialization and verification still need subsequent coherent contracts; full M2 remains open.
