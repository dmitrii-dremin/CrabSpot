# Java 21 String reference programs

The main fixture takes four arguments, interns equal arguments and literals, reads a static String constant through actual `getstatic` bytecode, and locks through two references to the same pooled value. On Zulu HotSpot and OpenJ9, the retained flags, initializer count, synchronized counter and argument count were `127/1/1/4`. An external observer also verified that the program retained its actual argument array and that the initializer saw the canonical literal. With an empty argument array the program returns before those operations. [Implementation contract](m2-string-constants.md).

| Probe | Observed behavior |
| --- | --- |
| Static constants during initialization | A superclass initializer reads two String constants from its subclass while that subclass is initializing. Both fields already hold the expected canonical values. The subclass's integer constant is 41 and the final four observations are `41/1/41/3`. The readers use emitted bytecode to prevent javac from inlining the fields. |
| Two defining loaders | The loaders define the same class bytes independently. Both literals, a static String constant and a subsequent call to intern return the same pooled reference across those loaders. |
| First observed call to intern | On the tested builds, HotSpot returned the supplied dynamically constructed receiver. OpenJ9 returned a distinct equal object. Both consistently returned the canonical object on subsequent calls. The reference process cannot inspect whether an equal entry already existed. A controlled empty CrabSpot pool can test the specified first-insertion rule directly. [String.intern](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/String.html#intern()) and [JVMS §5.1](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.1). |
| Literal encodings | The cases include NUL, Latin-1, a surrogate pair, isolated surrogate units and distinct composed and decomposed spellings. Two distinct String and UTF8 pool entries in one class produce one canonical object. A wide pool index exceeds 255. A valid maximum-length modified UTF-8 entry occupies 65,535 bytes and represents 21,845 isolated low surrogates. Both VMs returned code-unit hash −82,434,753 for that input. |
| Invalid load category | A String operand to `ldc2_w` produces VerifyError. HotSpot reported it during reflective method lookup and OpenJ9 during class loading. A separate driver preserves the first field write before reaching the invalid class. |
| Real Java String methods | The broader application calls `length`, `charAt`, `hashCode` and `equals`. Both VMs returned flags 63 and two hashes of −1,902,190,381. This is a control for later execution of the supplied Java library bodies. |

**Argument transport.** A Java observer constructs nine arguments from explicit UTF-16 units, including two fresh empty Strings, an option-like token, a space, a supplementary character and a final argument containing NUL and an isolated low surrogate. Both reference VMs returned `9/127/0` for count, content flags and pre-intern identity flags. Separately, the runner launches each VM with five real OS arguments and reports the delivered units as ASCII hex. On the original Windows host, both Java launchers delivered the euro sign followed by two question marks for the euro-and-rocket input. The output includes an independently checked hash of the delivered units. [Original Windows observations](../../tests/fixtures/string-constants/observed-windows-argv.json).

**Reproduction.** Set `JAVA_HOME` to a Java 21 HotSpot JDK and supply the pinned OpenJ9 executable for the secondary run. Each VM runs the archived and freshly compiled or encoded classes in separate processes. Each pass checks 35 observations and two native argument reports. Pinned builds replay the archived interning results exactly. Other HotSpot builds may return either the original receiver or a previously pooled object on the first observed intern call. The checker still requires equal contents and canonical identity across all later calls and both loaders. Native reports retain per-process identity observations and compare delivered units across runs. The maximum-length class exceeds the parser fuzzer's 64 KiB input ceiling, so the runner restores the exact `.class.bin` bytes for JVM loading. The public application staging helper selects only the application's own definitions.
