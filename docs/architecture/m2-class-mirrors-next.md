# Canonical class objects for verified directory applications

Proposal for exact-contract planning after the single-thread monitor review. Implementation requires a separate contract and readback.

Let an ordinary `main(String[])` compare `Base.class` with an object's actual class, store and reload the resulting `Class<?>`, and synchronize on that class object across a call to a static synchronized method. The current engine resolves reference types and distinguishes static-method locks by defining `ClassId`. A class literal and `Object.getClass()` would expose that identity to Java code for the first time. They also let a catch block distinguish the precise runtime class of a future VM-created throwable. [Java 21 class literals](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.8.2), [Java 21 Object.getClass](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Object.html#getClass()).

## Why this precedes exceptions and Strings

The current interpreter dispatches supplied `Throwable` references. VM-produced errors use a diagnostic category. In the supplied Zulu 21.0.7 image, `Throwable.<clinit>` starts by loading `Throwable.class` and calling `Class.desiredAssertionStatus()`. It also allocates arrays and calls `Collections.emptyList()`. `Throwable` has fields for the cause, suppressed exceptions, message and stack data. `NullPointerException.getMessage()` can reach a distinct VM native. Assigning the desired `ClassId` to zeroed storage would leave Java-observable library state unjustified. Some exception classes permit VM construction with disabled suppression or an unwritable stack trace. That permission is specific to those classes and does not resolve class initialization, cause semantics, array cloning or native access. [Throwable](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Throwable.html), [ArithmeticException](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/ArithmeticException.html), [NullPointerException](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/NullPointerException.html).

Real String literals and arguments would enable a wider range of application inputs. They also require exact UTF-16 data, literal interning across callers, valid representation for the supplied class library, and a defined policy for argument identity. In the same image `String(char[])` delegates to code using the empty String literal or `StringUTF16`; both `StringLatin1.<clinit>` and `StringUTF16.<clinit>` use class literals and assertion status. UTF16 also queries a native endian predicate. A class-object facility serves both paths, while providing executable behavior of its own. These dependencies describe this measured Java library. Each supported platform image needs independently validated class shapes and evidence.

## Proposed boundary

* The runtime owns canonical, heap-affine Java references for each represented non-array `ClassId` and each array type identified by rank and primitive kind or defining component identity. A mirror's runtime type is the designated bootstrap `java/lang/Class`, including the mirror representing `Class` itself. Validate the platform role, verified hierarchy and closed-image membership. Keep raw mirror issuance private. Return objects through ordinary locals, fields, reference arrays, equality, casts, returns and monitors. Pin how host raw instance allocation or bytecode `new Class` is distinguished from VM-issued mirrors. Class bodies must never observe made-up class-loader/module/hidden fields through such an object.
* Resolve `ldc` and `ldc_w CONSTANT_Class` from the actual caller and initiating loader, with existing access and admission checks, including array components. A literal performs no active use of the represented class. `int[].class` has a real array Class constant. Javac emits wrapper `TYPE` field reads for `int.class` and `void.class`; their bootstrap scope needs a later decision. Resolution/linkage failure persistence and absent host prerequisites must have separate, typed treatment. Check repeat sites, two separate CP slots and lookup from two defining loaders.
* Bind exactly the genuine bootstrap `Object.getClass()Ljava/lang/Class;` native declaration through the real method resolver. Track receiver selection, null precedence, checked identity, call location, fuel, policy and any retained CP success. Return the mirror of the actual receiver type, including array receivers, covariant locals and mirrors. Inspect actual javac Methodref owner encodings and the current array-owner restriction before fixing the contract. A name match in another class or an arbitrary native declaration grants no authority.
* Explicit monitor operations on a class object's `HeapRef` must reach the same ownership key as the implicit lock of the represented class's static synchronized method. Use the real mirror registry to recognize that reference. Keep ordinary objects, similarly named classes from different loaders and the distinct array mirrors independent. Opening an implicit static lock should preserve the current monitor resource policy without requiring eager mirrors for all classes.
* Extend closed-image assembly to admit the actual bootstrap Class type and required verified ancestors. Class is currently available as a verifier fact. Preserve proof, preparation and heap-affinity checks. The genuine `Class.<clinit>` invokes `registerNatives`; the exact contract must spell out when initialization is required, and the implementation must either execute its prerequisites or report a typed unavailable operation. Do not set a lifecycle success bit on the strength of issuing a mirror. Pin a safe barrier on operations that would expose unsupported Class object state, including virtual calls through an `Object`-typed receiver. An explicitly supported passive literal must not enable arbitrary Class-library execution on an incomplete Java object.
* Set checked quotas for actual mirror count/storage, retained strong roots and resolution/allocation work. Share each entry throughout its heap lifetime; a failed insertion leaves no published mirror or claimed identity and a retry can succeed. Report resource exhaustion as a host error under the existing profile. Specify charges for canonical hits, lazy first use and array keys without repeated descriptor copying. Preserve older body-only kernel behavior and the verified launcher entry. The exact contract must choose a finite initialization/native binding strategy before dispatch.

## Test and ownership plan

Run physical `crabspot run` and the public effect-reporting API on a javac-produced program. Check `Derived.class == ((Base)new Derived()).getClass()`, `Class.class == Derived.class.getClass()`, repeated literals in independent methods, an interface literal, primitive and reference array mirrors including nested arrays, equality after fields/arrays, and absence of a class initializer's marker until subsequent active use. Record both reference JVMs' effects and the actual CP tags/opcodes. A reference-only observer may call `Thread.holdsLock` to confirm the class-lock identity. In CrabSpot compare execution at recursion limits one and two to prove the explicit mirror and static synchronized callee acquire the same key. Include a distinct-class control, same-name/different-loader runtime cases, foreign heaps and resource failures. Under the existing VM exception materialization policy, a null `getClass` control can establish original call-site reporting and retained effects.

The coordinator's development probes already supply five original Java 21 classes. Zulu HotSpot and Semeru OpenJ9 each launch the application successfully, report `127/3/1 false/false` through a separate observer and give five true identity comparisons across two defining loaders. The current CrabSpot launcher stops at `Dependencies / UnsupportedPlatformReference`, CP index 28. These are preimplementation controls. In a separate six-path exception fixture both JVMs report `12/12/12/1`, preserve each rethrown identity, record a null cause and return observably different division and array-bound message text. CrabSpot stops at `fail(I)I` PC 40, invoked at PC 3. The source, artifact hashes and raw vendor outcomes are in the coordinator's `mirror-reference-v1` and `vm-exception-probes-v1` archives.

The runtime worker can own mirror identity, heap/type integration, native declaration binding and allocation guards. The engine worker can own CP/receiver entry, monitor key normalization, verified launcher composition and independent tests. The coordinator can own genuine source provenance, physical launch, public effect replay, differential class-loader controls and combined verification. Review exact heap ownership and lifecycle rules before implementation.

In parallel, collect baseline Java observations for a later first catchable `idiv`/`irem` exception: exact class and superclass catches, rethrow identity across frames, an uncaught path, cause and post-construction `initCause`, suppression, stack trace exposure, localized messages and human-readable uncaught diagnostics. Compare actual vendor outputs separately, with cold single-event runs to avoid accidentally specifying optimizer exception reuse. Save first committed field writes, trap location and initializer outcomes. A later proposal can select one real exception family, genuinely establish its bootstrap state and dispatch it at the faulting frame within the same execution budgets. Broad exception materialization, diagnostic Strings, native reflection, class loaders as Java objects, primitive mirrors, JNI, concurrency and full M2 acceptance remain open.
