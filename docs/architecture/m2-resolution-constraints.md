# Checked member resolution in the running interpreter

**Frozen for bounded implementation dispatch, 5 November 2026.** The technical director, coordinator and both component reviewers completed the feasibility readback. This increment connects the accepted loading domain to the runtime constant-pool entries reached by an original Java caller. A caller that writes a field and invokes a body across defining loaders can observe the same object on its return path. A descriptor disagreement produces a symbolic Java linkage failure before the resolved member is used. Implementation acceptance requires the frozen component reviews and full combined gate.

## Identities and normative boundary

D is the class or interface containing the constant-pool entry, C is the symbolic owner named by its CONSTANT_Class, E is the actual declaring class or interface of the resolved field or method, and S is a method selected for one invocation. Resolve C in the initiating namespace of D's defining loader. Perform the existing class accessibility, member lookup and member access checks. Upon success impose each nominal descriptor leaf between the **defining loaders of D and E**. This applies to a field type, every parameter and the return type of an ordinary class or interface method, including array element class/interface names at any rank. A primitive leaf and void contribute no equality. Equality can be recorded before either loader initiates the leaf type. A disagreement retracts the current insertion and retains previous insertions. The new path uses the same ledger as checked definition, delegation and preparation. [JVMS 5.3.4](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.3.4), [5.4.3.2](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.2), [5.4.3.3](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.3) and [5.4.3.4](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.4).

Use D's immutable symbolic field/method descriptor. Ordinary successful lookup guarantees exact UTF-16 name and descriptor equality with E's declaration. Emit parameter leaves in declaration order and then the return leaf, including repeated spellings at distinct positions. Consume field descriptors once in field order. The specification states the obligations as a set. Original multi-leaf probes with a preexisting split on Q establish the chosen deterministic prefix on both tested VMs. A split on the second leaf retains the first agreement. Rank and argument computational width have no effect on the leaf's spelling. For same defining loaders the entire resolution imposes zero ledger insertions. For a cross-loader member even a null argument or an as-yet-unexecuted callee requires its nominal signature constraints.

D, C, E and S each have a distinct purpose. Access to the symbolic owner precedes the search for a declaration. Member accessibility uses E and the qualified symbolic-owner rules, including loader-qualified runtime packages. A protected instance receiver restriction computed at resolution is stored with success and enforced against each actual receiver later. Selection of an override, default or special-super body uses the existing class graph; preparation imposes overriding/selection agreements on the proper declarations. S's loader interprets its actual body, fields, class symbols and declared argument/result checks. The managed heap, interpreter call frame, class initialization state and verifier proofs supply separate facts. [JVMS 5.4.2](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.2), [5.4.4](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.4), [5.4.6](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.6).

    pub max_prepared_classes: u64,  // default 65_536

    Field(FieldId), Method(MethodId), Failure(MemberResolutionFailure),

impl LoadingDomain {
    pub fn enable_member_resolution(&mut self, limits: MemberResolutionLimits)
        -> Result<(), Box<MemberResolutionError>>;

## Persistent resolution transaction

1. Keep the operation's existing profile, heap snapshot, origin/role, CP tag, structural name/descriptor, opcode/version and operand-extraction gates. They can differ between bytecodes. Shape-only inspection before popping arguments does not resolve a CP entry. A host root passed by MethodId has no invented CP slot. All actual CP resolution routes, including static reads/writes, initialization tokens and constructor-only paths, eventually use the same per-field/per-method transaction.
2. Once the opcode accepts this CP symbol structurally and requests resolution, probe the domain table. A terminal success reconstructs the prior symbolic-owner/declared-member/protected-qualifier result. A terminal failure reissues its original symbolic Java category. Structural tag mismatches, a forbidden initializer name for this opcode or unsupported signature/profile never read an incompatible terminal value. An existing hit requires neither capacity for an additional record nor a second member search, class-name lookup, access decision or ledger insertion.
3. Cold miss preflights site count, checked count addition and capacity for **one** permanent result before cold resolution/leaf insertion. Failure is host with no new record or equality. Resolve C by actual initiation in D's defining loader, check availability in the heap, class accessibility, class/interface kind where applicable, lookup, and member access. Keep the current class/field/interface search order, ordinary class-method and interface-method fallback and explicit unsupported nest/array/signature-polymorphic paths. An absent actual initiation is distinct from an accessible admitted owner with no matching member. Class accessibility precedes method-tag/owner-kind as in the existing services. Fieldrefs permit class or interface owners. The real declaring ClassId comes from the looked-up FieldId/MethodId.
4. After successful access, emit descriptor agreements in the specified order, applying the existing single-insertion ledger atomics. No eager loading, ticket or graph clone is required for a descriptor leaf. On a direct constraint conflict commit Failure(LinkageError) to the reserved slot and retain only earlier successful leaves. Other direct, permanently decidable resolution failures publish NoSuchField, NoSuchMethod, IllegalAccess or IncompatibleClassChange respectively. IncompatibleClassChange here means a Methodref-to-interface or InterfaceMethodref-to-class **at symbolic owner resolution**, not a later category/receiver/selection failure. Successful resolution publishes the actual declaration and access witness. Insertion/counter publication after the last fallible operation must be infallible. No partial cache value, displaced previous terminal or provisional index may escape on a host failure. Domain mutation is exclusive and callback-free.
5. A retryable host failure during cold resolution leaves the site vacant and preserves earlier committed leaves, charged work and earlier heap effects. Missing host binding/layout, invalid origin/metadata, foreign admission, capacity, work, allocation, unsupported nest/module/signature-polymorphic/array-owner or access prerequisite are host. A true Java failure at a later instruction stage also leaves a successfully resolved CP value published. At capacity previously terminal sites can still be reused. The identical entry is reused across supported bytecodes and executions of this D, including different caller methods, receivers and compatible snapshots. A failed record preserves the symbolic category. A VM-allocated Throwable object and Java exception identity remain beyond this profile. [JVMS 5.4.3](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3).

## Instruction, preparation and value boundaries

| Uses | After a CP success |
| --- | --- |
| getfield / putfield | Check instance category, write/final authority, receiver/bounds of access, normalization, value identity and assignment under E; then observe/commit actual instance field. Keep existing null/protected receiver and constructor-specific early-own rules. |
| getstatic / putstatic | Check actual static category, role and final authority. Use E's static slot. Under an initialization session retain the existing checked continuation, request E's initialization and do the read/write once on resume. A failed initialization retains CP success. |
| invokevirtual / invokeinterface | Use the resolved method in ordinary receiver checks/virtual or interface selection for this actual receiver. Check abstract/conflict/access/finality and selected-body preparation at their existing stages. S may differ on two uses of the same site. |
| ordinary invokespecial | Preserve ordinary special/start rules including direct-superinterface and ACC_SUPER lookup, receiver and abstract checks; selection may use a nearer super declaration than E. |
| invokestatic | Require a static actual declaration, prepare/cache/check frame budgets before typed operand extraction as today, validate actual arguments, then request E's initialization where enabled. Run E's Code with E's constant pool and actual static state. |
| invokespecial of a constructor | Accept only the construction-capable path and structurally valid constructor Methodref. Resolve class method/access/descriptor first. Afterwards enforce the existing E==symbolic C constructor rule, category, allocation/this/direct-super/role checks, preparation, chaining, alias promotion/invalidation and final-write authority. An inherited accessible ancestor constructor can resolve and constrain yet fail the per-instruction owner rule. |

A permanently resolved CP member gives no authority to bypass category, nullness, receiver comparability, assignment, source handle, allowed final writes, constructor state, initialization or checked frame transfers. Existing return/argument checks continue to use the actual body declaration. A checked context skips only the conservative nominal matching-declaration scan in check_method_reference_profile *after* ordinary shape/staticness and actual-receiver checks, since each admitted receiver class has domain preparation evidence. Otherwise return a retryable host UnprovenSelection carrying E, S and descriptor position. This guard is read-only, preserves CP success, performs no insertions and covers special selection shapes for which preparation has no corresponding equality. Skip the entire boundary check when E and S have the same defining loader. Primitive-only different-loader signatures have zero leaves. At a host root without a symbolic CP reference there is no D/E/S relation to invent. Ordinary checked argument/return services still apply. ## Capacity, accounting and diagnostics

Retained member counters are independent from existing LoadingDomainUsage. Their limits are inclusive. Increment once per newly witnessed root or terminal CP key. Reject checked overflow as AccountingOverflow(resource); representable over-limit carries resource, configured limit and required total. Deterministically charge/open existing FieldResolutionOptions for its established operations and a cumulative LoadingWorkLimits meter for new domain integration. The old entry points' budgets and precedence remain stable. Sites store fixed-size scalar keys/outcomes only. Resolution capacity is never reserved proportional to a configured maximum. Rehashing a scalar key must not rescan arbitrarily long names.

Use prior loading accounting for actual initiating lookups, descriptor leaf/forest operations, preparation validation and producers. New meter charges one Work per checked witness or terminal-table probe (including a hit); one Work for a new scalar insertion-capacity check and one Scratch entry before reserving one new persistent table position (the slot becomes terminal without a fresh late check). On a miss preflight Work/limits/allocation before reserving, charged capacity in spare storage conveys no record. For deterministic context opening, traverse the domain registry's canonical definition vector once in index order. Fund one Work per probed definition, including a class absent from this heap, then one Work per admitted class and one per inspected direct edge in addition to witness probes and actual initiating lookups. Count observed heap classes and compare with the heap's scalar admitted count. An internal registry iterator and a checked heap-membership test suffice. This path requires no sort, temporary copied graph or public identity issuer. For field/method cold resolution charge one full descriptor UTF+Work before traversing it to enumerate leaves, even if all leaves are primitive or the defining loaders coincide. If that returns false, perform actual lookup in E then S (stop if E has none) with normal lookup charges. A missing E/S agreement can be repaired by lawful domain operations after context drop. A cold wrong-kind or inaccessible member never funds descriptor *constraint* traversal. Precharge all newly added actual allocations before mutation. Document existing limits versus newly funded operations, including semantic UTF comparisons in new cold lookup and ledger paths. Each new arbitrary-length name hash/comparison must have full UTF+Work coverage or a charged scalar memoization from the same domain. Fixed-arity scalar CP lookups compare no names.
