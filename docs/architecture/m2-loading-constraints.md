# Initiating loaders and preparation-time loading constraints

Director-approved implementation contract, 2026-11-05. The baseline is the approved modern class verifier. This contract adds checked runtime loading state and the constraints imposed by preparation of one ordinary definition. It requires neither executing a class loader nor running class initializers. Reference JDKs supply test observations only.

## Authority and class identity

Introduce an opt-in owning runtime type `LoadingDomain`. Construct it with an empty, newly created DefinitionRegistry. The domain owns that registry for its entire lifetime and exposes only a shared reference to it. It may create further loaders, define additional ordinary classes and record delegation through the checked domain APIs below. It has no clone, mutable registry getter, ownership extraction, reset or importer of caller-claimed history. Dropping it releases the registry and all records together. Existing users can continue using standalone DefinitionRegistry, including its defining-only lookup and byte-source helper. The checked path has no callback into application code and no unchecked fallback to that helper. Domain views can build existing immutable hierarchy plans and verification environments. Their registry borrow prevents mutation of the domain while such a borrow is live. A HierarchyPlan owns its facts and therefore requires validation against the current domain when subsequently supplied.

Class identity is the registry-issued ClassId. LoaderId identifies a loader only in that registry. The key of an initiating record is an exact ordinary internal binary name in UTF-16 plus a loader. Each direct definition creates its own initiating record. Delegation can associate other loaders with the same identity. A constraint is a name-specific equality between *future or present* meanings of that name. A loader can belong to an equality component containing a known identity while still having no initiating record. That loader's lookup must return None until it actually initiates a load. An equality does not load or define a class. Array rank and primitive descriptors have no standalone identities in this service. A legal ordinary class may be named I or V. Recognize primitive descriptors only in descriptor context. [JVMS 5.3 and 5.3.4](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.3.4).

## Public operations

Expose these from crabspot-runtime. All handles remain opaque. A checked operation context borrows its domain mutably and tracks accepted work across calls. A caller may create a fresh context with different work limits after inspecting a failure. Permanent relations belong to the domain. No persistent quota can be enlarged by opening another context.

Validate loader handles left-to-right, then validate the supplied ordinary binary spelling with the current registry's internal-name rules and 65,535-unit cap. This order also applies to impose and constrained, whose Rust argument list starts with name. Invalid supplied binary names use Registry wrapping the existing ordinary-name diagnostic, including the existing unsupported-array spelling error. InvalidMetadata is for inconsistent internal canonical metadata. For record_initiation next validate the target ClassId in this registry and compare its canonical name. Reject a wrong returned name as the explicit symbolic NoClassDefFound outcome before considering records or constraints. A foreign handle is a host Registry error. Exact duplicate record of the same ClassId is idempotent. Different actual records for the same loader/name, or disagreeing ClassIds in components being joined, fail with symbolic LinkageError. Preserve previous compact identities for diagnostics. For distinct loaders, constrained reports only connectivity by imposed equalities. Two independent loaders with actual records of the same ClassId remain unconstrained until joined. Such a join consumes one union even if both already have the same known identity. A valid self-equality always holds, creates no node, and succeeds with the same validation on absent names. Queries allocate no persistent names or pairs.

A direct define first validates loader/name and checks the actual initiating record. A prior direct or delegated initiation rejects derivation as a symbolic duplicate-definition LinkageError *before* parsing, including attempts with malformed bytes. If no actual record exists, perform the registry's existing size/name/format validation in its published order. Direct definitions with a declared-name mismatch retain boxed Registry(NameMismatch) from that admission. WrongReturnedName specifically represents delegated class identity mismatch. Full Java translation of registry admission errors remains a separate derivation task. Only after successful admission checks, test the prospective fresh definition against the equality component. If another identity is already required, fail with symbolic LinkageError. Admit and publish the definition and initiating record in a single fail-before-publish transaction. A failure leaves definition_count, total bytes, defining lookup, all logical loading table counts and all existing bindings intact. Do not publish a provisional ClassId or expose one in diagnostics. A subsequent successful definition must be able to use the next unconsumed definition index. Narrow private factoring of registry admission is permitted. Its normal entry points keep their prior observable behavior and limits. Existing registry/parser internal allocation conventions are inherited only for their existing parsing/storage operations. Added table growth and staging must reserve fallibly. [JVMS 5.3.5](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.3.5).

## Persistent relation and failure publication

Use one name-specific equivalence relation. Joining components with different known ClassIds fails immediately. A successful merge preserves the unique known identity if either side has one. A later explicit record that disagrees with this identity fails before publication. Earlier successful insertions, including earlier constraints from the same preparation, survive a later failing insertion. This is per-insertion retraction. A later legal delegation or definition may succeed if all prior obligations permit it. Replay of a successful preparation is semantically idempotent and still pays for the inspection; the service does not issue a prepared-class lifecycle bit. [JVMS 5.3.4](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.3.4).

Represent retained spellings once and pairs as compact (name ID, loader ID) records. A union-by-size forest without destructive path compression gives bounded iterative root walks with no rollback journal. Ties choose the earlier created root. Each pair has a distinct optional actual initiation, and its root has an optional component identity. Count only accepted nonredundant unions, not a stored history of input edges. An equivalent representation requires the same observable effects and accounting. Semantic equality is exact UTF-16 units, including valid non-ASCII and surrogate units. Use scalar-key indexes or cached fingerprints with collision-correct equality. Rehashing must not scan all previously owned names without funding. A rejected operation may leave spare capacity, but publishes no names, pairs, initiating records, joins or partial registry state. Reserve on actual additions, never on policy maxima. Check arithmetic and reserve the entire small insertion before any visible mutation. No internal mutation on failed query or failed union may change equivalence, funded-work behavior or later public results.

## Preparation prerequisite and producer order

`prepare_constraints(plan)` covers only C=plan.root(). Its prerequisites are admitted canonical definitions and their completed initiating records for the hierarchy edges. The existing builder checks hierarchy shape/finality/cycles. Validate the root handle and every plan row, dependency-first in plan.classes() order, before imposing any constraint. For each canonical row inspect its direct superclass, then direct interfaces in classfile order. Check that each actual ClassId lies in the plan and equals the actual initiating record for the corresponding CP Class name under the *defining loader of that row*. Require the classfile edge count/order and root identity to agree with the plan. An absent initiating record is a structured MissingInitiation prerequisite, a different plan target is InconsistentHierarchy. An implied but unrecorded equivalence cannot supply a hierarchy edge. No implicit record or resolver callback during preparation. Include an interface's structural Object superclass here. Plans made by other registries, wrong-but-same-name delegation plans and externally unavailable hierarchy facts must fail before producer effects.

Use the root's actual superclass chain nearest first, then its full transitive superinterface set in the plan's deterministic dependency-first completion order (excluding C itself). Derive that set over classes and interfaces of this closure. A plan produced for this root contains only reachable classes. Deduplicate interface identities, including diamonds, while retaining classfile declaration order within each owner. The Object edge belongs to superclass traversal; never follow it as a superinterface dominance edge. First-error order across distinct declarations is a deterministic CrabSpot choice. HotSpot may enumerate different method declarations in a different order. Record any observed difference in surviving agreements separately from the required per-insertion effect and the measured parameter-before-result leaf order. All semantic selection operates solely on borrowed class/member metadata and nominal handles. The actual runtime receiver selector imposes access/category/receiver checks that belong to an invocation, so cannot directly implement this phase. [JVMS 5.4.2](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.2).

1. **Declared methods.** Bridge and synthetic instance methods participate under their real names, descriptors and flags. For each genuine instance method declared directly in C, in original method-table order, inspect matching declarations in superclass order then superinterface order. Initializers and static methods are outside both producer rules. A private overriding declaration cannot override. Match exact method name and complete descriptor. A public/protected ancestor target is overridable by an eligible declaration. For class-chain package-access targets use loader-qualified runtime package equality, including transitive overriding through intervening eligible declarations. A nearest-first scan may retain the packages of already-overridable declarations for this signature; private/static declarations neither extend nor block that set. Interfaces carry the access flags accepted by the version-aware parser. For each matched overridable target immediately emit the descriptor relation between C's defining loader and that target's declaring loader. [JVMS 5.4.5](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.5).
2. **Inherited implementations.** Visit every instance method declared by every retained superinterface in the order above. If C declares an instance method that can override it, rule 1 already processed it. Otherwise apply method selection with respect to C and this specific interface declaration. A private target selects itself, producing only reflexive constraints. For other targets search C then its actual superclass chain for the nearest instance declaration that can override the target. An abstract class declaration selected this way is still a declaration, with a defining loader. Skip static/private candidates for nonprivate targets. If no class-chain match exists, use the maximally specific superinterface declarations with that name/descriptor, excluding private/static candidates. A candidate is dominated if another eligible matching declaration is in its strict subinterface, including an abstract redeclaration. Exactly one nonabstract maximal selects that method, regardless of the order of any remaining abstract maximals. Without such a selection there is no declaring-loader pair to constrain: continue preparation. No preparation-time invocation error is invented for abstract-only or conflicting-default shapes. When selected, the pair is the *selected declaration's defining loader* and the original superinterface method's defining loader, which can both differ from C's. Rules apply with C a class or an interface. [JVMS 5.4.6](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.6).
3. For each emitted signature visit parameters left to right, then the result. The specification identifies the constrained types. Original JDK 21 partial-failure probes establish this implementation order: (P,Q)V and (P)Q keep an earlier P agreement when Q later conflicts, whereas (Q,P)V and (Q)P leave P unconstrained after the first Q conflict. A nominal type or a nominal array leaf supplies its underlying ordinary binary name. Void, primitive scalars and primitive array leaves emit no obligation. Duplicate leaves are visited and paid; the persistent mathematical relation remains idempotent. Descriptor spans are borrowed and bounded, with no force-loaded signature types. Prior successful individual leaf constraints survive later descriptor/selection/budget failures. Canonical admitted descriptors have valid grammar; malformed internal metadata fails structurally. No independently supplied prepared bit, host-selected target, array ClassId, nest approval or module-access claim is substituted for missing facts.

## Work counters, diagnostics and acceptance

The checked ledger has two budgets. Permanent counts reflect committed logical state and survive context replacement. Evaluation usage records paid work even when later work fails. Nothing charges by wall time. All units are inclusive checked u64. Default limits are host policy, including meaningful zero and u64::MAX overrides.

~~~rust
pub struct LoadingDomainLimits {
    pub max_names: u64, pub max_name_units: u64, pub max_pairs: u64,
    pub max_initiations: u64, pub max_unions: u64,
}
pub struct LoadingDomainUsage {
    pub names: u64, pub name_units: u64, pub pairs: u64,
    pub initiations: u64, pub unions: u64,
}
pub struct LoadingWorkLimits {
    pub max_utf16_units: u64, pub max_work_units: u64, pub max_scratch_entries: u64,
}
pub struct LoadingWorkUsage {
    pub utf16_units: u64, pub work_units: u64, pub scratch_entries: u64,
}
~~~

Defaults in declaration order are 65,536 / 4,194,304 / 262,144 / 131,072 / 262,144 for retained resources and 16,777,216 / 67,108,864 / 4,194,304 for a work context. Check new retained totals atomically in declaration order: first distinct spelling, its exact UTF-16 code units, newly needed (loader,name) records, new *actual* initiations, and independent component joins. On failure report the first exceeded resource and absolute required count, without consuming the batch. All lookups and semantic checks must precede reservation/publication. Existing names, existing equal bindings, reflexive, duplicate or transitively implied constraints add zero retained units. Two new distinct loaders joined on the same fresh name add one name, its length in units, two pairs, zero initiations and one union. Later recording the first actual identity for an existing pair adds exactly one initiation. Recording it on a previously absent pair creates that pair as well. Domain counts exclude capacities, isolated temporary entries, registry metadata and already-paid evaluation work. Physical capacity may be retained after a failed reserve. Raw allocator bookkeeping is bounded by the existing registry/parser policies separately.

All added variable-length operations must have proportional work paid before touching input/mutating state. A work request `(utf16_units,work_units,scratch_entries)` checks all next totals in that order and commits all together. A failed batch leaves all three at their previously accepted totals. Charge by these events:
- Each loader/class handle validation, inspected CP/metadata item, plan row, superclass/interface edge, declaration candidate, dominance candidate pair (including self), equality candidate spelling and visited union-find node (including root) costs one work. Reading two checked handles is two events even when identical. A reused internally validated handle needs no artificial revalidation. Reading a member's scalar flags/index from an already funded declaration is included. All loops over physical rows/edges/declarations are funded before inspection, including duplicates, static, private, special and unreachable-as-override candidates. Actual CP handle lookups are funded even if the string value is reused.
- Validate ordinary spelling length by its scalar length before a potentially long access. Each external operation's validated name scans its complete length for UTF and Work. This funding covers name grammar and one query fingerprint pass, including preparation of an insertion. A later exact equal-length spelling comparison pays its full comparison length in UTF and Work before comparison, including a cache/hash collision. Different lengths may short-circuit after the scalar candidate cost. Full descriptor scans, exact equal-length name/descriptor comparisons, class package boundary scans and spelling copies pay their entire examined/copy length in UTF and Work. A scalar equality of two IDs known to represent the same previously checked metadata avoids scanning and paying UTF. Use a bounded semantic scan for copying the immutable name during retention, paid before reserve. The existing parser/registry's own admission under its byte caps is a distinct service and keeps its historic charges. Added ledger/name work cannot hide inside a claimed registry lookup.
- Charge one work for scalar ledger name-index probe, each scalar pair-index probe and each requested nontrivial join/bind publication attempt that successfully reaches preflight, before retained-limit checks. Each visited root/parent node costs one work. Missing candidate paths cost no nonexistent root visits. Use checked union size and rank or deterministic equivalent bounds. Self-equality needs validated handles/name and no identity/pair lookup. Queries never allocate logical scratch or persistent records. For example on an empty ledger, querying the valid three-unit name p/K with one valid loader consumes (UTF=3, Work=5, Scratch=0): one handle check, three name units, one name-index probe. Reflexive impose/constrained of that name consume (3,5,0): two loader checks and the name scan. Neither needs a pair-index lookup. With exact capacity these operations succeed; the first insufficient work request retains previous paid events. A failed direct define must not charge for a fake published class.
- Every transient graph/list/visited/candidate/package/descriptor-leaf cache entry created in a context costs one scratch and one work before append/insertion. Before reserving known batches, fund the batch; no policy-sized reserve, no unchecked bulk copy. Scratch counts cumulative creations, including a repeated operation after dropping its temporary tables. Reusing an entry without allocating/copying it adds no new scratch unit. Fixed single-insertion staging (bounded at two pairs and one name) is scalar, zero scratch. Immutable borrowed slices/iterators require no independent charged entry; state which such representation is used. Each repeated ancestry/lookup scan is funded on actual examination. Algorithms may avoid unnecessary scans through identity caches or iterative visitation. Tests pin hand-countable persistent totals and mandatory per-event minima, exact self/query/empty work boundaries, and measured inclusive total/one-less pairs for traversal-dependent work. Different traversal optimizations may change measured work if corrected in review. Charge before examining a candidate or enqueueing an edge. No recursion proportional to class graph or union depth.
- Preparation validates all row/edge prerequisites before the first producer effect. Preflight or scratch failure in that prerequisite phase leaves the ledger intact. Thereafter stream one obligation at a time. Split immutable metadata, mutable ledger and mutable evaluation counters into disjoint borrows so emitting a borrowed descriptor leaf needs no whole-descriptor clone. The preparation stream does not precollect all constraints. It may collect a fixed descriptor's up-to-255 borrowed parameter spans, or walk the descriptor directly in declared order. Eagerly copying signatures/names into a repeated, persistent method-graph cache without audited bounds is outside this contract. Retain validated CP views and temporary flat state only while funded. Where an algorithm filters maxima, all actual pair and strict-ancestry steps must be funded. Repeated proof/prepare calls pay for inspections anew. Supply an upper-bound argument or hand-counted hostile case for each new scan family.

Define `LoadingConstraintResource::{Names,NameUnits,Pairs,Initiations,Unions,Utf16Units,WorkUnits,ScratchEntries}` and `LoadingDescriptorPosition::{Parameter(usize),Return}`. Expose a boxed error with public `kind: LoadingConstraintErrorKind`, `site: Option<LoadingPreparationSite>` and direct standard Error source where appropriate. A site records `class: ClassId` (plan root), optional `origin: MethodId` (declared C method or interface target generating this obligation), optional `related: MethodId` (ancestor target or selected implementation), optional `position: LoadingDescriptorPosition`. Direct ledger operations use None. Preparation prerequisites use a class-only site; later failures carry the applicable matched pair and signature position as soon as known. No copied long diagnostic strings or issued future identity. Runtime exports all public field types. Errors implement Debug, Display and Error. Exact error-kind payloads:

WrongReturnedName represents the NoClassDefFoundError category for a delegated load. DuplicateDerivation, InitiationConflict, DefinitionConflict and ConstraintConflict represent the LinkageError category of the checked operation. The distinct variants preserve its reason and actual IDs; define does not return a second ID on conflict. MissingInitiation and InconsistentHierarchy describe absent/contradictory preparation inputs, not evidence of a Java loading exception. Registry preserves the underlying error as its direct source. Include public usage accessors as above for inspection after errors (and after dropping the context). One optional compact accessor for reading domain usage through the mutable context is permitted. Source-based class loading, classpath search, exception object construction, verification error caching, modules, nest access, concurrency, unloading, hierarchy-time auto-initiation, heap/static slot allocation and method/field resolution-time constraints require separate contracts. The existing more conservative interpreter signature guard remains in force.
