# Registered static-call resolution and initialization

Status: bounded implementation approved by the technical director on 2026-11-04 after frozen source review and the 882-test workspace/795-test optimized integrated gate; see `m2-static-call-resolution-review.md`. The exact implementation contract was dispatched at baseline c58b3df after initialization implementation 6dbbef4 and its complete Linux/Windows evidence. Fresh hosted CI remains pending. Full M2 and complete JVM linkage remain open. No NanoSpec.

## Scope and governing rules

Extend registered, runtime-aware invokestatic to admitted classes and interfaces beyond the current declaration. Keep one engine, MethodId cache, shared graph/resolver and existing initialization continuation. No new opcode, heap, lifecycle table, loading mechanism or execution delegation is introduced.

The normative sources are [JVMS method resolution](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.3), [interface method resolution](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.4), [access control](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.4), and [invokestatic](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-6.html#jvms-6.5.invokestatic). Resolution precedes the instruction's static-category check. Class lookup includes superclass lookup and eligible interface fallback; interface lookup includes its declaration, public Object instance fallback and eligible superinterfaces. Superinterface static/private methods are not inherited through that fallback. Access and loading constraints apply to the resolved declaration. An instance result produces IncompatibleClassChangeError rather than searching again for a static candidate. Initialization concerns the actual declaring class/interface, not the symbolic owner. There is no receiver dispatch or overriding selection for invokestatic.

The implementation profile continues to use immutable admitted metadata and unnamed-module access. It does not establish full verifier/linker correctness, persistent runtime-constant-pool resolution/failure caching, native binding, synchronized invocation, nestmate access, String materialization, constructed linkage exceptions, constructors or Java startup. Those boundaries remain explicit failures, not fabricated success.

## Public runtime API

Add one method to the existing context; do not add new options or a parallel resolver:

```rust
impl FieldResolutionContext<'_> {
    pub fn resolve_static(
        &mut self, origin: ClassId, index: u16,
    ) -> Result<MethodId, MethodAccessError>;
}
```

The result is the actual declared static MethodId. It is not a prepared body, initialized class, access certificate reusable from another origin, or lifecycle token. The operation never reads Code, executes Java, changes static/instance values, allocates a Java object or initializes a class. It may consume shared work and retain successful loader/name bindings under existing context rules.

Reuse MethodAccessError and its direct Java categories; no new exception category or error wrapper is needed. Fix the existing UnsupportedSpecialMethod display wording to cover ordinary calls generally, without changing its variant or eligibility. Keep Error::source behavior intact. Only direct MethodAccessError::Java maps to the engine's existing symbolic/unsupported-VM policy. Missing source definitions, resolver failures, unsupported loader/nest boundaries, malformed metadata and wrapped Java-shaped errors remain host failures.

## Ordered resolution contract

1. Check the context snapshot, registered origin and actual admitted membership. Preserve heap/registry identity, layout-count and universe invalidation. Same-count replacement is not a valid substitute.
2. Read the origin's CP entry. Methodref is accepted; InterfaceMethodref requires the origin class-file major version to be at least 52. Other tags, unusable indices and malformed CP structure return InvalidConstant { origin, index }. The version/tag check precedes resolution callbacks and argument extraction. A Methodref naming an interface, or the converse, is a later owner-kind Java error, not an invalid CP tag.
3. Reuse the ordinary method-symbol parser: checked owner Class/Utf8, unsupported array-owner boundary, checked NameAndType/name/descriptor and initializer-name rejection. Constructors and clinit remain excluded. The admitted parser already validates grammar; inspect borrowed signature spans with existing descriptor work rules, without retaining copied nominal names. No new static shape-before-pop API is needed.
4. Resolve the symbolic owner through the context's origin-defining-loader bindings/resolver. Apply symbolic-owner access before owner-kind checking. Reuse existing complete class/interface method resolution, including signature-polymorphic unsupported handling and its established deterministic interface fallback representative. Do not replace this with a static-only declaration search.
5. Apply existing member access to the resolved declaration. Public succeeds; package access uses both package UTF-16 name and defining LoaderId; private is allowed only from the actual declaring ClassId, with other origins returning UnsupportedNestAccess. Protected static members outside the package require the origin's class-only ancestry to include the actual declarer. They do not require a receiver, symbolic-owner comparability, or an interface-as-class subclass relation. A nonpublic declaring superclass is not separately rejected when a lawful accessible symbolic owner exposes its public member.
6. Apply the conservative nominal loading boundary below, even for all-null eventual arguments. Then require ACC_STATIC. A nonstatic result is direct Java IncompatibleClassChange. Do not skip it to search a parent, do not perform a receiver-null check, and do not turn an abstract instance candidate into AbstractMethodError. Valid admitted metadata cannot have a static abstract declaration. Native/synchronized static declarations may resolve; their unsupported execution is handled by preparation.
7. Return the actual MethodId. There is no selected override, final-method-chain audit, special-call owner relation or actual receiver graph to inspect.

Refactor the shared existing resolver only as far as necessary to separate its common symbolic resolution/access/loading phase from required static-versus-instance category. Existing b6/b7/b9 wrappers must preserve their current phase order, diagnostics and exact work charges. In particular, instance paths must still reject static declarations at their established point.

The protected-access distinction depends on the resolved member's flags, not merely the b8 opcode. If a malformed b8 resolves a protected nonstatic member outside the package, preserve the existing symbolic-owner/origin comparability access check before the eventual static-category error. Do not globally disable that common access check for the new call kind. There is still no actual receiver to inspect.

Interface static methods are usable when actually declared by the symbolic interface. A static method on a parent interface alone is not found through its child interface or an implementing class. A public Object instance fallback, default, or abstract interface candidate can resolve, but cannot pass this instruction's static-category check. Multiple eligible defaults must use the existing resolution rule and then category handling; do not silently bypass candidates or introduce invocation selection. Private interface statics are usable only from that same actual interface under this profile.

## Descriptor identities and loading boundary

The existing exact name/descriptor matcher determines the declaration; retain semantic UTF-16 equality rather than CP-index or display-string identity. The call-site descriptor and resolved declaration therefore have the same spelling, except for signature-polymorphic resolution which remains unsupported.

If any parameter or result contains a nominal class/interface leaf, require the origin's defining loader to equal the actual declaring method's defining loader. Otherwise return UnsupportedLoadingConstraint { origin, method } before static-category checking and before stack extraction, including all-null arguments/results. Primitive-only and primitive-leaf-array descriptors do not impose this conservative rejection. A different symbolic-owner loader does not itself forbid a result when origin and actual declarer loaders agree. No virtual override audit is appropriate: a static call has no selected receiver declaration or intervening overriding chain.

After resolution, existing check_method_reference_profile(method, None), check_method_arguments and check_method_return use the actual declaring method and its loader. Descriptor type resolution remains identity-only, without an added caller-access requirement on hidden parameter/result classes. Null preserves existing value-validation shortcuts, but never bypasses the resolution-time loader boundary. Actual non-null object/array compatibility uses the already implemented assignment service and explicit universe.

Keep prepared signatures compact: computational kinds and return tags only. Borrow immutable descriptor spans for work/value checks; no owned nominal tree or new resolved-signature cache. Because accepted caller/declarer nominal identities share a defining loader, no separate copied call-site return signature is necessary. Full cross-loader loading constraints remain open rather than inferred from matching names.

## Eligible engine profiles and compatibility

All registry-backed Services::Fields executions use resolve_static for every b8, including same-class calls: ordinary instance-body, supplied-Throwable, static-memory, composed static-memory/Throwable profiles, and InitializationSession. No additional public execution entry point is required. A body profile's other capabilities remain unchanged: adding method resolution does not enable static field opcodes in a profile that previously rejected them, or automatically initialize classes outside InitializationSession.

Standalone ClassFile execution and heap-only execution retain the old same-class resolve_call implementation, eligibility, errors and budgets. They have no registry/context from which to resolve another class. Host selection of a root MethodId also retains its existing explicit-host semantics; the new access checks apply to symbolic b8 instructions, not an invented caller for root selection.

Registered same-class b8 deliberately gains normal context work and structured resolution outcomes. Tests expecting the old registered MissingDeclaredMethod, wrong-owner-kind host error, or no lookup work must migrate narrowly to the new service. There is no special same-class shortcut that bypasses access/loading/category checks. Legacy standalone expectations and all b6/b7/b9 checks remain unchanged.

## Interpreter order and continuations

For registered b8, preserve the current static-call pipeline, replacing only target resolution:

1. Charge the instruction's fuel once and retain the real current MethodId/invoke PC. Call resolve_static(current.owner(), index). Route direct Java failures through the same method_failure/vm_completion path as other calls. In ordinary body profiles these produce existing symbolic outcomes; supplied-Throwable/session profiles return UnsupportedVmException before handler search. Host failures remain boxed MethodAccess errors with caller/invoke provenance.
2. Use the returned MethodId to locate the actual owning ClassFile/CP. Prepare a missing cache entry as ordinary Static, with existing special-name/native/abstract/synchronized exclusions, Code decode and handler validation. On every cache hit verify both non-initializer and static eligibility. Share the entry across symbolic aliases/subclass owners that resolve to the same complete MethodId; never share across distinct defining identities.
3. Check active-frame/slot reservation before typed argument extraction, preserving existing static ordering. Reverse-pop computational arguments using the prepared shape, restore their order, run validate_args, check_method_reference_profile(method, None), and check_method_arguments. Category-two values occupy two local slots; there is no receiver/local-zero offset. Preparation, resource and argument failures occur before target initialization in this bounded profile.
4. In host-controlled body profiles, activate the target with the usual shared engine/frame/cache limits. In InitializationSession, retain target, arguments and next PC in the existing pending call, restore the suspended caller's PC to the invoke instruction, and request initialization of method.owner(). Resume once with existing cache-role/reservation checks; do not resolve, validate arguments, pop or debit instruction fuel again.
5. Every callee uses its own CP and declaring origin for later fields, casts, static/virtual/interface/special calls and diagnostics. Return validation and transfer remain the existing actual-declarer checks and caller-capacity protocol. Effects survive later failures. A supplied Error escaping target initialization is searched against the caller's original b8 PC; a later target-body throw is ordinary callee dispatch. Existing session abort/erroneous/retained-root semantics are unchanged.

The pre-initialization host preparation and argument checks are the existing bounded API policy, not a claim to implement native binding, verifier failures or every full-JVM timing guarantee. Valid supported bytecode is the behavioral oracle scope. Unsupported native/synchronized bodies must not become fake initialized-and-executed methods.

## Work and resource policy

Use the existing FieldResolutionOptions counters and successful binding cache. Snapshot/origin checks add no graph traversal. The shared signature inspector charges the complete reference-bearing descriptor on each inspection, including cached symbolic targets and null values; numeric-only inspection retains its existing zero extra type-work rule. Preserve the inspector's current incremental failure-counter behavior, not the initialization constant planner's separate atomic precharge rule.

Owner binding hits use existing no-callback behavior. Missing bindings check symbol/unit allowances before callback/publication. Class lookup charges each visited class and examined method declaration under the current resolver. Interface fallback retains all existing node/edge/method/candidate-pair/dominance charges, including self pairs and duplicate edges before enqueue. Protected access uses the existing class-only ancestry charges. No receiver-chain/override scan is added. Illustrative incremental lookup costs after context construction, with cached owner and numeric descriptor: a class or interface declaring exactly one target method costs one owner-node plus one declaration step; a child with no methods resolving that target from its parent costs three steps. Tests must pin inclusive/failing limits and cumulative mixed field/method work.

Every call redoes required origin-sensitive symbolic checks even if the target's prepared body is cached. The cache saves Code preparation, not authorization or reference-value checks. Initialization resumption reuses the already checked target and does not redo resolution. All metadata traversal/drop is iterative; temporary work/visited/candidate storage is fallibly reserved from actual admitted data. No new persistent method-resolution cache, copied graph or policy-sized allocation is introduced.
