# Canonical class mirrors in a verified application

**Frozen implementation contract.** The single-thread monitor increment passed its bounded native gate. Both component owners reviewed the exact APIs, ownership, ordering and acceptance scope. The coordinator controls implementation dispatch. The first target is the ordinary verified directory launcher, including the original five-class and storage programs in the coordinator's mirror archive. This target includes array mirrors, passive class literals, a real `Object.getClass` binding and static monitor identity. Reflection, Java `ClassLoader` objects, arbitrary native binding, general `Class` library service, primitive/void mirrors, exception materialization, and initialization of a full Java runtime are later increments.

## Representation and authority

* Use the existing canonical `ReferenceType::{Class(ClassId),Array{dimensions,element,defining_loader}}` for the **represented** type. Rank is 1..255, with primitive leaf loader = designated bootstrap and nominal leaf loader = its defining loader. A ClassId names either an ordinary class or an interface. Never key by the caller, textual spelling, structural hierarchy or CP slot. The Java **runtime type** of every mirror, including `Class.class`, is the one designated bootstrap `java/lang/Class`. No `ClassId` is invented for arrays.
* Issue a real `Reference` through a dedicated VM heap payload. Store the canonical represented type in that payload and one heap-owned `ReferenceType -> HeapRef` index. Publish the payload and index together after checked quotas and all three fallible reserves for arena, index and ordered root vector. Issued references work in ordinary fields/statics, all reference arguments/returns, local/stack operations, arrays (`Class[]` and compatible supertypes), casts, `instanceof`, equality and monitors. `instance_class` and `reference_type` recognize them as the designated `Class`. `children` yields zero Java field children for this opaque VM payload; its metadata IDs are strong metadata references. Expose a borrowing, exact-size, allocation-free root iterator ordered by mirror issuance for a future collector. The present arena never collects or reuses a mirror. Different heaps never share a reference.
* Put mirror binding on a pristine managed heap with a bound reference universe and admitted graph, before any arena entry or initialization claim exists. Allow idempotent matching redeclaration with no reset; incompatible role, registry, layout or ceilings is a typed failure. Validate checked role/registry/bootstrap name and public ordinary superclass-Object shape. Require authoritative final Class metadata and genuine `Object.getClass` flags when authorizing their respective operations. Use a deterministic, lazy declaration check for the sole supported native so an existing numeric app need not resolve an unused native. For minimal caller-supplied images, validate the final Class role at binding and the native method role lazily as specified below. No trusted production fixture or replacement boot body.
* Binding seals ordinary allocation of the designated Class identity. Direct host `allocate_instance(Class)` and bytecode `new Class` take a typed host unsupported path. For `new`, resolve its class, access and existing instantiability prerequisites, then refuse before requesting initialization or allocating; do not publish an uninitialized alias or fake VM error. Reject even if code would only pop or lock the unfinished reference. Arrays of Class remain lawful. HotSpot rejected these raw allocations with `IllegalAccessError`, while OpenJ9 executed the two unused/lock-only forms; classify the sealed VM policy separately. Both vendors deny the actual inaccessible constructor. A raw ordinary object present before binding cannot be reinterpreted as a mirror. Legacy heaps without a binding retain existing low-level semantics.
* Never let incomplete Class fields look like ordinary zeroed Java state. Reads and writes of fields on an opaque mirror stop at a typed host boundary following existing symbolic resolution and ordinary per-use access/category checks. Resolve and select Java methods normally, then explicitly refuse entry into `java/lang/Class` instance bodies on an actual mirror until their backing state is implemented. Other Java code can handle a `Class` reference, including its own helpers and ordinary inherited methods that require no hidden state. Genuine static active use of Class retains its actual initializer and ordinary unsupported `registerNatives` behavior. Passive type literals, mirror creation, a getClass invocation and array creation perform no active initialization of the represented type or of Class. No privileged initializer-success bit or empty `<clinit>` substitute. [Class](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Class.html), [JVMS §5.5](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.5)

## `ldc` and type resolution

* The existing numeric decoder and constant categories continue to lead. Accept only `ldc`/`ldc_w` of a checked `CONSTANT_Class` in the enabled profile, after normal root/Code preflight and instruction fuel. A wide constant index remains a full u16. `ldc2_w Class` remains invalid under Code verification. Other reference constant variants keep their established boundaries. Both `I` and `V` are ordinary binary names in a non-array Class CP entry; `[I`, `[LI;` and `[[LI;` denote three different array types. Primitive scalar class literals use wrapper `TYPE` fields and are outside the scope.
* Resolve in the actual current method's ClassId/initiating loader with checked type-name access (`FieldResolutionContext::resolve_reference_type`). Check ultimate nominal component accessibility even for arrays and use loader-qualified runtime packages. No consulting an unrelated classpath, implicit defining-loader fallback, component guessing or blind delegation. For this closed-image service missing actual initiation or layout is host-unavailable and repairable when opening a compatible heap/context. The sealed launcher will normally refuse an externally absent dependency sooner. A genuine loader failure recorded by a Java loader is a different semantic event. In the original `late.Peer` control both VMs retained the first NCDFE at the original site after the loader later defined Peer; no Java-loader source/terminal NCDFE issuer is introduced here.
* Domain-owned class-literal/array-member-owner resolution records bind `(origin ClassId, actual Class CP index)` to a canonical ReferenceType or permanent `IllegalAccess`. A new dedicated store is explicitly enabled for checked mirror execution; keep existing `member_site` observation/limits separate. All cold prerequisites precede effects, even for the warm member use on a smaller heap. Terminal Java class failure can replay with only the origin, as for earlier member failure. Warm class success revalidates membership, current universe and leaf affinity before use; host prerequisites, corruption, allocation and policy errors never become terminal. A successful class resolution can survive a later mirror mint, operand stack or member-resolution failure. Repeated calls, duplicate aliases and two independent Class CP slots should separate CP-site cost from heap canonicality. Other legacy Class CP consumers retain their existing immutable-fact checks and supported failure boundaries as specified below. [JVMS §5.4.3.1](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-5.html#jvms-5.4.3.1), [JVMS `ldc`](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-6.html#jvms-6.5.ldc)

## Actual `Object.getClass` and class monitors

* Binding is to the checked immutable MethodId of the *declared* bootstrap `java/lang/Object.getClass()Ljava/lang/Class;`, public final native instance, with no Code, static/synchronized/abstract or other incompatible invocation role. Validate descriptor's return identity via the current loader agreements. Neither callsite spelling nor an arbitrary native overload binds the service. For ordinary nominal owners preserve member resolution/cache, access, loading constraints D→E, category, null check, receiver, selected declaration and current CP. Interface-method fallback to public Object, `invokespecial` super and inherited subclass symbols must reach the same genuine declaration through the ordinary rules. An overloaded Java `getClass(int)` executes its own Code. An unbound native remains an explicit unsupported native; never issue a hosted UnsatisfiedLinkError object. Static invocation of a resolved instance native gets the original ICCE boundary.
* The checked array-symbolic `Methodref [I.getClass` and a Methodref owner `Object` with an array receiver both work. Array-owner access checks resolve the original Class CP including its leaf, then getClass resolution chooses the actual Object declaration and imposes caller↔Object descriptor agreements under the existing member-site limits. Retain structural array owner alongside E in the private member record; do not use Object's identity as a fictitious symbolic array owner. For a reference array symbol validate receiver compatibility with that resolved array, allowing real covariance. For interface invocation with an actual array receiver permit only the implemented marker interface cases prescribed by the type universe. Other array-owned methods keep their current separately reported boundaries (including `clone`). Wrong member tag, wrong categories, unsupported special forms, forbidden prior-construction receiver and wrong receiver relations keep normal precedence. Class-boxed native call handling must not slow every reference through a full hierarchy audit of array overrides.
* Integrate the intrinsic at the native-call boundary after selection, originating invoke's typed argument extraction, role checks and descriptor guarantees, prior to trying to prepare Java Code for a native. No second bytecode loop, Java activation of an invented implementation, fictitious b1/areturn, or general native override table. Consume the invoking instruction's fuel once, execute one bounded native operation in the same evaluation, then push the result in the original caller. No Java Code bytes/handler entries/Java frame/recursion debit for a native with no Java activation; pin how existing caller max_stack validation and mirror issuance interact. Errors carry the original method, caller invoke PC and call_site as appropriate. Canonically validate receiver including array payload, get its exact runtime ReferenceType, issue/reuse the corresponding Class reference. Executing `Class.class.getClass()` returns the same Class mirror. All existing low-level numeric/instance/initialization-only profiles stay explicit; root MethodId APIs must not enable arbitrary selected native execution.
* Normalize key for explicit c2/c3 after reference validation and before the existing monitor step. A nominal mirror maps to `MonitorKey::Class(represented ClassId)`; an array mirror has an ordinary identity key based on its canonical heap reference. All other object keys stay distinct. An implicit synchronized static call continues to use the actual declaring ClassId, with no mirror issuance and no changed charge. When an instance-synchronized method locks its receiver, apply the same normalization if the receiver is a mirror. Alias/copy/store/dispatch cannot split or fuse keys. The existing cross-frame strict rules, diagnostics, completion funding and ledger teardown are inherited. [Object.getClass](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Object.html#getClass())

Return boxed errors on these APIs. Wrap once as an execution `ClassMirror` or relevant nested method-access/launcher setup error. Direct permanent Java IllegalAccess on a checked `ldc` maps to the existing unsupported VM exception production; no Java throwable is fabricated. All host resource/metadata/shape errors remain host diagnoses. Add distinct instance-level errors `ReservedClassObject { class }` (ordinary allocation) and `OpaqueClassObject { class }` (field operation).

## Cache and compatibility details

Pure checked **resolution** is enabled by the domain's class-site store, independent of heap mirror binding. `resolve_class_mirror_type` requires a checked member context, origin and enabled store, but may run without mint authority. Inspect the outer Class tag and the domain cache before requiring a reference universe for cold type resolution or warm success validation. Warm permanent class/member failure replay requires only the origin and existing checked context and its normal work, even if a smaller heap has no Class layout, leaf, defining-class layout or Class binding. Warm success/cold resolution requires the corresponding universe and admitted leaf/E; missing prerequisites are typed host refusals without altering terminal successes. `read_method_symbol` must allow the narrow getClass array symbolic member shape through to this domain transaction before an unbound-heap check. A legacy context/domain with no class-site store retains the old `UnsupportedArrayOwner`. A checked store on an unbound heap can therefore resolve or replay structural method/class outcomes, but cannot mint or execute the intrinsic. Revalidate the full bound profile only at session creation and VM object use; never gate a permanent failure on possession of new heap state.

The class-site table is domain-owned and referenced from the existing checked member authority, with its own cap/count. Enabling the mirror feature does not replace a host's immutable loader policy. An existing terminal member failure can replay without a symbolic layout, as specified by the member contract. For cold array-owned `getClass` resolution, use the existing member ticket/cap/charge first and retain the original Class CP index from the Methodref. Run the inner class-site transaction next. A terminal class-access denial is observable at that Class slot even if no structural array owner was produced to commit a member record. Clear the outer ticket's diagnostic site on all returns. After successful class resolution, a wrong owner/tag or member access/linkage error can be recorded at the member site. A subsequent successful method resolution publishes the actual `Object` MethodId before opcode-category, null, receiver, native-profile and mirror quota checks. No observation query seeds a record. A completed cold operation may have a paid class-site success even when member resolution later fails. Each layer's failed reservation publishes no row and retains earlier paid work according to that layer's meter. Keep CP Class cache and terminal member cache distinct from the heap mirror cache, which returns a canonical **object** independent of sites. No late Java NCDFE producer is added; absent true initiating-loader facts stay repairable for direct low-level APIs. `checkcast`, instance field/array resolution, construction and other existing CP consumers retain their preexisting contracts; all checked consumers agree on immutable nominal identity and access. Universal JVM class-load error caching remains open.

Internally allow the checked member record's symbolic owner (including in the resolved method) to be structural `ReferenceType`. Existing field owners and nominal method owners occupy `ReferenceType::Class`; keep old validation/charges/returned outcomes. A warm structural owner revalidates the array rank, primitive or actually admitted nominal leaf and its actual defining loader before using E. Record validation ties the array entry to the original owning Class CP and the bound native declaration, E=bootstrap Object, no protected receiver qualifier and legal record family/tag. Preserve full checks on registry/loader/snapshot, including on a smaller heap; do not use the `Class` class of the mirror as an array owner. Clearing the opaque member capability or using a heap lacking the boot Class role must never turn a warmed array method into a legacy executable native. `member_site` still exposes `Method(actual MethodId)` or the established terminal Java failure. A valid array `Methodref` reused by b8 resolves to the same method then fails ICCE. A separate array `InterfaceMethodref` used by b9 has the wrong symbolic owner kind and gets ICCE after resolving array access. `invokespecial` with an array symbolic owner is outside this special selection profile and must fail before issuing a result; nominal `invokespecial super.getClass` uses its ordinary ACC_SUPER/receiver checks and succeeds. Other array-owned names remain unsupported and must never create false NoSuchMethod success/failure facts. For array receiver and a nominal interface owner, check actual marker/interface conformance according to this operation (rather than the verifier's relaxed class-to-interface assignments). Ordinary instance subclasses cannot replace a final Object declaration.

`new Class` after resolution on a bound heap gives `ReservedClassObject` at the actual bytecode and precedes initializer planning/work, allocation, alias rewrite and constructor authority. Ordinary heap field helpers and the interpreter method entry (including host/direct preselected MethodId with a mirror receiver) enforce `OpaqueClassObject` before exposing layout-backed Class state. Numeric unrelated calls and instance fields on application objects which *hold* a mirror keep ordinary behavior. Root direct preselected native IDs remain closed unless the shared bytecode path defined here actually resolved and selected the bound native. No standard native can be forged via a synthetic overload, malformed flags, an Object-like name in another loader, `Class.<init>`, or a mutable host setter.

Do not replay class initialization or widen repeated engine roots. The mirror profile is scoped to one checked session but cache identities have separate lifetimes: the class-site outcome survives context drop in its domain, the same heap retains its issuance-order roots, and a different compatible heap may mint its own distinct mirrors on warm successes. If new native/selection helpers need a checked readonly role test across crate boundaries, expose only scalar identity or vetted method/receiver services; no caller-provided boolean authorizes dispatch.
